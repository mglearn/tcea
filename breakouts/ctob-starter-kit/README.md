# CTOB Starter Kit

Everything you need to build your own **Critical Thinking Online Breakouts (CTOBs)** —
self-contained, browser-based reasoning activities with a built-in **7-language switcher**
(English, Spanish, Vietnamese, Arabic, Hindi, Urdu, Chinese; Arabic & Urdu right-to-left),
no accounts, no server, and no data collection.

This kit is a **self-contained copy** of the runtime engine, the build tooling, the reusable
teacher-support content, the full design blueprint, and one **complete working example** you can
play and pull apart. Nothing here calls back to the parent project.

> **Read [`ctob_project_pack.md`](ctob_project_pack.md) first.** It is the blueprint — the engine
> and translations are commodity; the *quality* of a CTOB lives in the clue/lock writing (§2).

## Quickstart

**1. Try the example.** Open `example/index.html` in a browser (or serve the folder), play the
breakout, and use the 🌐 menu to switch English ⇄ Spanish. The other five languages fall back to
English automatically — that fallback is what lets you ship English first and translate later.

**2. Make your own breakout.** Copy `example/student.html` + `example/example.js` and edit the
data. Keep the shape:
- `window.BREAKOUT = { id, band, confetti, UI:{en,…}, CONTENT:{en,…} }`
- **6 clues**, exactly **one a true-but-off-topic decoy**.
- **4 locks — one of each type:** `seq` (order), `mc` (choose), `multi` (sort evidence: 3 strong + 1 decoy), `word` (name it).
- **Every lock's `reason` names the thinking move.** Gameplay fields stay identical across languages; only text translates. See project pack §2–3.

**3. Add the teacher-support pages** (UDL / ELPS / lesson-plan guide) for your suite:
```bash
# a) edit _pd/suite/en.json — replace "example" with your suite key + a worked example
# b) edit gen-pd-pages.js — set the SUITES map (key = folder name, plus its theme colors)
node build-pd.js       # → assets/*-core-i18n.js + assets/pd-suite-i18n.js
node gen-pd-pages.js   # → <suite>/udl.html, elps.html, guide.html
```
The UDL/ELPS/guide cores are **generic** — reuse them unchanged; only `_pd/suite/en.json` is
suite-specific. To ship the support pages in all 7 languages, add `es.json`, `vi.json`, `ar.json`,
`hi.json`, `ur.json`, `zh.json` beside each `en.json` (same keys, translated values) and re-run
`build-pd.js`. Link the three pages from your correlation page; `pd-supports.js` + the engine's
`BreakoutI18n.extend()` localize the link labels.

**4. Generate a teacher answer key** (optional):
```bash
node build-answer-key.js <args> '<password>'   # password from argv/env — NEVER commit it
```
Adapt the `buildPlaintext()` section to read your breakout files. PBKDF2-SHA256 (250k) → AES-256-GCM,
decrypted client-side; only ciphertext ships.

**5. Verify before you ship** (do not skip — project pack §14):
- Structural check per breakout: 6 clues / 1 decoy, 4 locks one-of-each, `multi` = 3 strong + 1 false, `seq` pad-keys + answer order, `mc.answerIndex`, `word.answer` non-empty; **all 7 languages same array order/count.**
- **Solve every breakout in a real headless browser** (win fires, no console errors) in English + one non-English + one RTL language. A lock that never renders (e.g. a missing `id`) only shows up here.

## Translation notes

- Authoring translations with parallel AI agents works well — one breakout (or one core file) each.
- **JSON-safety rule:** never put a straight ASCII double-quote (`"`) inside a translated string —
  it breaks the JSON. Use typographic quotes (`「」`, `“ ”`, `« »`). Straight apostrophes are fine.
- Keep every array the **same length and order** as English so translated text zips cleanly onto the
  gameplay structure.
