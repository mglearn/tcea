# Project Roles and RACI Matrix: Staff MFA Rollout

**R = Responsible** - performs the work  
**A = Accountable** - owns the result / final decision  
**C = Consulted** - provides input before action  
**I = Informed** - receives updates

## Role Definitions

| Role | Project Responsibility |
|---|---|
| Sponsor | Removes organizational barriers; approves major schedule/scope changes |
| CTO | Project lead; accountable for implementation and cross-functional coordination |
| Infrastructure Manager | Owns technical configuration, testing, monitoring, legacy-system review |
| Help Desk Manager | Owns support readiness, recovery workflow, ticket reporting |
| HR Director | Validates employee populations and onboarding/offboarding impacts |
| Communications Director | Reviews districtwide messages and leadership talking points |
| Instructional Technology Lead | Creates staff training and campus support resources |
| Principals | Campus-level reinforcement and local escalation |
| Finance | Budget review and purchasing support |

## Decision Escalation Rules

1. Routine configuration decisions stay with the technical team within approved standards.
2. Changes affecting all employees, schedule, budget, or district policy move to the CTO.
3. Enforcement delays, scope expansion, or material budget changes move to the sponsor.
4. Legal, HR, or employee-relations questions are not decided by the project team alone; they are referred to the appropriate district office.

## RACI Quality Check

- Each row has one clear **A**.
- Avoid assigning **R** to large groups when an individual owner can be named.
- Revisit the matrix when scope or staffing changes.
- A RACI matrix clarifies responsibility; it does not replace communication or collaboration.
