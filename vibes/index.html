01 / Vision

Name the problem

Start with what educators or students need to do. Keep your first version small enough to finish and test.

Use a descriptive name, not a product slogan.
Vision checkIf you cannot describe the need in one or two sentences, narrow the project before asking a chatbot to write code.
02 / Instruct

Write the build instructions

A clear specification makes a free chatbot much more effective. Say what it must do, what the user sees, and what it must avoid.

Put one feature per line. Three is enough for a first version.
Free-tier strategyAsk the chatbot for a brief specification first. Review it, then request the complete first version in a separate message.
03 / Build

Create the smallest usable version

Build the basic interaction, test it in a browser, and make one improvement at a time. Avoid adding accounts, databases, or AI APIs to a first project.

Ask for the entire working file, without placeholder code. Save it as index.html and open it locally in a browser.
04 / Evaluate

Check before you share

Run the tool yourself using fictional information. Check whether students can use it, rather than relying on the chatbot's claim that the code works.

Evaluation mattersThis checklist documents your tests; checking a box does not certify that the tool is accessible, secure, or compliant with district policy.
05 / Ship

Put the tool where it can be used

Write plain-language instructions. Review school policies before publishing and keep an editable copy of the source.

Shipping safelyStatic hosting can serve a free HTML file. This studio does not publish sites or check district approval on your behalf.
